Framework Runtime Comparison

NestJS Backend vs React Frontend & Hydration Mechanics

Evaluators rigorously test candidates on the operational boundaries between server and client. Here is how NestJS (Inversion of Control) and React 19 (Fiber reconciler) differ and how hydration is safeguarded.

⚙️ NestJS 11 (Backend Engine) IoC / DI
  • Inversion of Control (IoC): Services are decorated with @Injectable(). The NestJS DI container automatically resolves and instantiates dependencies as singletons.
  • Request Pipeline: Inbound HTTP $\to$ Global Middleware $\to$ Guards (AuthGuard) $\to$ Interceptors $\to$ Validation Pipes (ValidationPipe) $\to$ Controller $\to$ Service.
  • Concurrency: Executes on Node's single-threaded libuv event loop. CPU-heavy scrypt crypto is offloaded to the internal worker thread pool.
⚛️ React 19 & Next.js 16 (Frontend) Virtual DOM
  • Component Tree: Unidirectional state flow. UI updates trigger Fiber reconciliation and incremental diffing.
  • Server Components (RSC): Render to static HTML on the server with zero client bundle footprint.
  • Client Components ('use client'): Hydrate in the browser to enable hooks, DOM event listeners, Web Audio contexts, and canvas mounting.
🌊 Hydration in Detail & Why Phaser 3 CANNOT Run on Node.js Zero Hydration Warnings

What Hydration Is: Next.js renders JSX components to a plain HTML string on the server. The browser receives this HTML and paints it immediately (First Contentful Paint). Next, the client JavaScript bundle downloads, walks the existing DOM tree, and binds event listeners (onClick, onChange). The server-rendered HTML string and initial client virtual DOM must match identically, or a hydration mismatch occurs.

The Phaser 3 Problem: Phaser is an arcade canvas engine. At import time, it accesses browser-only globals: window, document, HTMLCanvasElement, WebGLRenderingContext. If imported on the server, Node.js throws a fatal error: ReferenceError: window is not defined.

DevPulse Solution: In apps/web/features/office/OfficeView.tsx, Phaser is dynamically imported strictly inside a client-side useEffect hook: 

// apps/web/features/office/OfficeView.tsx: Dynamic client-only import
useEffect(() => {
  let cancelled = false;
  (async () => {
    // window and WebGL exist ONLY here in the browser:
    const [{ createGame }] = await Promise.all([
      import('@/game/createGame'),
      document.fonts.ready,
    ]);
    if (cancelled || !containerRef.current) return;
    controllerRef.current = createGame(containerRef.current, { ...options });
  })();
  return () => { cancelled = true; controllerRef.current?.destroy(); };
}, []);
Security Architecture

Mira's Authentication, 2FA & Social Engine

Originally prototyped as a standalone Better-Auth module on origin/transcn-changes, then re-engineered into an enterprise-grade stateless JWT + rotating refresh token system with universal 2FA and remote session eviction.

🔑 Scrypt Password Hashing Memory-Hard
Unicode NFKC normalized passwords hashed using Node's crypto.scrypt: $$N = 32768, \quad r = 8, \quad p = 1$$ 16-byte random salt, 64-byte derived key, 64 MB memory limit. Verified via constant-time timingSafeEqual.
🔄 Dual Token Rotation Anti-Theft
15-minute JWT access_token (signature verified without DB lookup) + 30-day random refresh_token (SHA-256 in DB). Rotated on every use. Presenting a reused token past the 30s grace window revokes the entire familyId device family.
🛡️ Universal 2FA (TOTP) RFC 6238
TOTP secrets encrypted at rest via AES-256-GCM with HKDF key derivation. Enforced on email/password AND OAuth logins. Anti-replay monotonic step tracking + 10 hashed backup codes.
🌐 Triple OAuth 2.0 with PKCE Google · GitHub · 42
Integrates Google, GitHub, and 42 Intranet. Generates cryptographically secure state and PKCE code_verifier (SHA-256 challenge S256). Prevents authorization code injection attacks.
📱 Single Device Lock & Eviction SessionGateway
Users can only be active on one device at a time. New logins generate a 15-minute takeover link with cookie binding hashes. Upon confirmation, SessionGateway emits session:ended over WebSockets, instantly kicking stale tabs.

Game Engine Core

Roy's 2D Virtual Office: Phaser 3, Movement & Procedural Art

The 2D virtual office is rendered in WebGL with static scenery texture baking, an 18-attribute DNA character recipe generator, speed-clamped movement synchronization, sitting physics, and live in-game layout editing.

🎨 Static Texture Baking 60 FPS
Static tiles (floors, solid walls, room borders) are baked once at startup into 512px RenderTexture chunks at depth = 0. Eliminates hundreds of discrete graphics draw calls every frame.
🧬 19-Char DNA Recipe recipe.ts
Characters and desks are procedurally generated from a 19-character code: "1" + 18 base-36 digits (build, skin, hair, outfit, vibe). Desks decorate themselves dynamically based on the owner's vibe (props, plants, monitors).
🪑 Sitting Mechanics Interactions
Dwelling on a free seat for 500 ms snaps the avatar to seat coordinates, clears physics velocity, disables body collision, and faces the chair's orientation. Holding movement for 500 ms dismounts to a free tile.
⏱️ 20Hz Throttled Movement & Speed Clamping
Packets transmit over Socket.io as [x, y, dir, moving, seated] flagged volatile (stale packets are dropped). The backend enforces speed clamping: $$\text{maxDistance} = 1.6 \times \text{WALK\_SPEED} (170\text{ px/s}) \times \Delta t + \text{TILE} (32\text{ px})$$ Prevents speed-hacking while allowing teleportation at entrance spawns. Flood budget limits users to 40 moves/s.
📐 100ms Linear Interpolation Buffer
Remote players are rendered 100 ms in the past using a 30-snapshot ring buffer: $$k = \frac{t_{\text{render}} - t_A}{t_B - t_A}, \quad x = x_A + (x_B - x_A) \times k$$ Positional jumps exceeding 192 px flush the buffer and teleport immediately. Depth is dynamically sorted by feet coordinates: $$\text{depth} = 10 + \frac{y}{100000}$$
Collaborative Project Management

Zakaria's Real-Time Jira Kanban Board

A high-performance project board featuring Jira-style issue keys (DP-101), atomic sequential numbering, an $O(1)$ fractional ranking drag-and-drop engine, and live desk paper stack rendering.

🔢 Fractional Ranking Algorithm (O(1) Writes) rules.ts
Standard Kanban boards update every item's index in a column on move ($O(N)$ writes). DevPulse implements fractional indexing, requiring only an $O(1)$ write on the moved card: 
export function rankBetween(before: number | null, after: number | null): number {
  if (before === null && after === null) return 1;
  if (before === null) return after! - 1;
  if (after === null) return before! + 1;
  return (before + after) / 2;
}
If floating-point distance drops below 1e-6 (needsRebalance), the column rebalances sequentially with integers ($1, 2, 3\dots$).
🔒 PostgreSQL Advisory Locks on Issue Numbers tasks.service.ts
Sequential numbering per workspace (PREFIX-1, PREFIX-2) is protected against concurrent creation race conditions using transactional advisory locks: 
await tx.$executeRaw`
  SELECT pg_advisory_xact_lock(hashtext(${workspaceId}))
`;
const numAgg = await tx.task.aggregate({
  where: { workspaceId },
  _max: { number: true },

const number = (numAgg._max.number ?? 0) + 1;
Guarantees gapless, conflict-free issue keys under heavy concurrent multi-user load.

Real-Time Audio Engineering

WebRTC Proximity Voice & 3D Spatial Audio

Peer-to-peer audio mesh utilizing the Web Audio API for HRTF directional panning, orientation-based sound rotation, distance gain attenuation curves, and server-gated acoustic room isolation.

🎧 Web Audio API HRTF 3D Panner spatial.ts
Every peer audio stream connects to a PannerNode configured with panningModel: 'HRTF' and rolloffFactor: 0:
  • Audio coordinates are transformed by the listener's avatar facing direction (up, down, left, right).
  • Speakers standing to your character's right pan exclusively to your right earphone.
  • Audio parameters smoothly interpolate over 80 ms via setTargetAtTime(val, t, 0.08) to prevent audio pops.
📉 Mathematical Distance Gain Curves Web Audio
Volume is regulated by a chained GainNode:

Open Office (Cosine Falloff): Full volume within 1 tile (32 px); smooth cosine decay to silence at 4 tiles (128 px):

$$\text{gain} = 0.5 \times \left(1 + \cos\left(\pi \cdot \frac{\text{dist} - 1}{3}\right)\right)$$

Meeting Rooms: All occupants hear each other across the entire room with a 30% floor at the farthest wall.

🚪 Server-Side Acoustic Room Isolation (`talk-rule.ts`) Security Rule 
// apps/api/src/voice/talk-rule.ts: Physical acoustic separation
export function withinEarshot(a: Spot | null, b: Spot | null): boolean {
  if (!a || !b) return false;

  // Acoustic isolation: People in different rooms cannot hear each other
  if ((a.room?.id ?? null) !== (b.room?.id ?? null)) return false;

  // Meeting room: Whole room is audible to occupants
  if (a.room?.kind === 'meeting') return true;

  // Open space: Max distance is 4 tiles (128 px)
  return Math.hypot(a.x - b.x, a.y - b.y) <= EARSHOT_PX;
}
Physical Space Enforcement

Meeting Room Timetable & Physical Room Colliders

Meeting rooms are protected by a scheduling timetable with advisory locks. When a meeting is in session, non-attendees are physically barred by arcade physics colliders and ejected from the room.

📅 Timetable Scheduling Rules booking-rules.ts
  • Bookings snap to 15-minute slot intervals (:00, :15, :30, :45).
  • Duration: minimum 15 minutes, maximum 4 hours (240 mins).
  • Advance booking: up to 30 days ahead; maximum 30 attendees.
  • Double-booking race conditions are eliminated using PostgreSQL transaction advisory locks: pg_advisory_xact_lock(hashtext('booking::')).
🚧 Physical Arcade Physics Barricade OfficeScene.ts
  • When a booking begins, Phaser checks if the local user is an attendee.
  • If not invited, an invisible Arcade physics collider activates across the door opening, making the room physically impassable.
  • If an unauthorized avatar is already standing inside when the meeting starts, they are automatically ejected to the office entrance spawn!
🔒 Multi-Layered Meeting Security
Room privacy is enforced across all 3 layers: 1. Physical Layer: Phaser colliders prevent walking into the room. 2. Audio Layer: Server's bookingAllows() blocks WebRTC signaling to non-attendees. 3. Chat Layer: Chat messages are filtered by bookingId so meeting history remains strictly private to attendees.

const N = 32768, R = 8, P = 1, KEY_LENGTH = 64;
const MAX_MEMORY = 128 * N * R * 2; // 64 MB

export async function hashPassword(password: string): Promise<string> {
  const salt = randomBytes(16);
  const normalized = password.normalize('NFKC');
  const hash = await scryptAsync(normalized, salt, KEY_LENGTH, {
    cost: N, blockSize: R, parallelization: P, maxmem: MAX_MEMORY,
  });
  return ['scrypt', N, R, P, salt.toString('base64'), hash.toString('base64')].join('$');
}
